1. Goal and scope

What you asked for

  • A program that runs locally on this PC
  • Source on the left, auto-updating preview on the right
  • Autocomplete of functions, like the Typst web app
  • Your own standalone desktop app (chosen over VS Code + Tinymist)

Done means

  • Open a folder, edit a .typ file, see the page update as you type (well under a second)
  • Typing #, . or ( offers functions and parameters with docs
  • Errors are underlined in the editor and listed below
  • One click exports a PDF
  • Works with no internet (except first download of @preview packages)

Deliberately not included

  • Accounts, cloud sync, real-time collaboration
  • A plugin system, git integration, spell check
  • macOS / Linux builds (Windows 11 only for now)
  • Writing our own compiler or language analysis

This machine: Windows 11, Typst 0.15.1 (winget), Node.js, Rust/Cargo, VS Code. Tinymist is not installed yet.

2. Approach: build the shell, reuse the brains

The hard parts of a Typst editor — understanding the language for autocomplete, and re-rendering only what changed for a fast preview — already exist in Tinymist, the open-source Typst language server that powers the VS Code extension. The app is a thin window around it: we build the editor shell and file handling, and run Tinymist as a hidden helper process.

The preview frame talks directly to Tinymist’s local preview server over a websocket; the app does not sit in that path. The Rust backend never parses Typst — it only moves bytes and manages processes.

4. Data flow

You type a character

  1. Editor sends the change to Tinymist (didChange) — the file is not saved.
  2. Tinymist recompiles incrementally from memory.
  3. It pushes changed page parts to the preview frame, and errors back to the editor.

Autocomplete

  1. Trigger: #, ., (, ,, @ or Ctrl+Space.
  2. Editor asks Tinymist for completions at the cursor.
  3. Popup shows functions, parameters, your own #let names, labels, citations, fonts, file paths — with docs.

Save and export

  1. Ctrl+S writes the file (plus autosave after 1 s idle, on by default).
  2. Export saves first, then runs typst compile on the main file.
  3. Result path shown in the status bar with “Open” and “Show in folder”.

Jumping between sides

  1. Click text in the preview → editor cursor moves to that source line.
  2. Ctrl+click in the editor (or cursor move, optional) → preview scrolls to that spot.
  3. Both are features of Tinymist’s preview; we only relay the messages.

The “main file”

Projects with several files need one entry point. Rule: the app previews the file you pin as main (right-click → “Set as main file”); if nothing is pinned, it previews the file you are editing. The choice is stored in the app settings per folder.

Template names in the mockup are illustrative.

  • Browse — search by name or keyword, filter by category; each card shows thumbnail, name, version, one-line description.
  • Details — larger preview, author, licence, link to its Typst Universe page.
  • Use template — choose a folder and name; the app runs typst init @preview/name:version there and opens the new project.
  • My templates — “Save current project as template” copies it to a templates folder in your documents; using one copies it back out. Works offline.
  • Sharing your own templates with others — publish them to Typst Universe (done outside the app); they then appear in everyone’s market.

The catalogue is downloaded from Typst’s public package index and cached, so the last-seen list still shows when offline; creating from an online template needs internet once.

6. Error handling and safety

SituationBehaviour
Typst compile errorSquiggle + Problems entry; preview keeps the last good pages
Tinymist crashes or hangsAuto-restart once and re-send open files; if it fails again, show the banner with a manual Restart
typst.exe not found on exportClear message with a button to choose its location in Settings
File changed on disk by another programReload if you have no unsaved edits; otherwise ask “Keep mine / Load from disk”
Closing with unsaved changesPrompt to save; autosave makes this rare
Save fails (disk full, read-only)Keep the text in the editor, show the error, never discard edits
Package needs downloading while offlineShown as a normal compile error from Typst
Template market opened while offlineShows the cached catalogue with an “offline” badge; “My templates” fully works; online templates say they need internet
Creating from a template fails (download error, folder not empty)Show Typst’s message; nothing is left half-created
Update check fails (offline, server down)Silent; try again at next start. Never blocks the app
Update download is corrupt or not signed by our keyRejected by the updater; current version keeps running

Safety: the web side may only read/write inside the opened folder (Tauri capability scope). The preview server binds to 127.0.0.1 only. The window’s content-security policy allows frames from localhost; the only remote hosts the app contacts are Typst’s package server (template catalogue) and the update host. Templates are Typst markup, which cannot run programs on your PC. Helper processes are killed when the app closes.

Testing: one automated test for the only non-trivial logic we write — the LSP message framing in the bridge (split and partial messages). Everything else is covered by a short manual smoke checklist per phase (open, type, complete, error, export, restart helper).

8. Implementation phases

Phase 01–2 days
Feasibility spike (throwaway). Prove the three risky links before designing anything around them: (a) Tauri starts Tinymist and exchanges LSP messages, (b) CodeMirror shows Tinymist completions, (c) Tinymist’s preview renders inside an embedded frame and updates on unsaved edits. Exit: all three work, or we switch to the fallback noted in Risks.
Phase 1~1 week
Usable editor (MVP). Open folder, open/edit/save one file, live preview, autocomplete + hover + parameter hints, error squiggles and Problems list, Export PDF, status bar, draggable split. Exit: you can write a real document in it start to finish.
Phase 2~1 week
Multi-file comfort. File tree with create/rename/delete, main-file pin, outline, click-to-jump both ways, Format, quick open, find/replace, light/dark theme, settings, recent folders, autosave, external-change handling.
Phase 3~2–3 days
Package it for other people. Windows installer with Tinymist bundled, app icon, .typ file association, PNG/SVG export options, crash-restart polish. First-run check that offers to locate or download Typst if typst.exe is missing on that PC.
Phase 4~2–3 days
Update system. Generate the signing key pair; a release script that builds, signs and uploads the installer plus a small latest.json to the update host. In the app: check at startup and from Settings → “Check for updates”; show a quiet notice “Version X is available — Install and restart”; never install while you have unsaved work, never without a click. Each update also carries the newer bundled Tinymist. Exit: version 1.0.0 installed on a second PC updates itself to 1.0.1.
Phase 5~4–5 days
Template market. Catalogue download and cache, gallery with search and category filter, details view, “Use template” via typst init, and local “My templates” (save / use). Shipped as the first real update, which also exercises the update system. Exit: from the Welcome screen you can pick a thesis template and be typing in it within a minute.
Lateronly if wanted
Snippets, multiple tabs, spell check, symbol picker, package browser. None of these are designed here.

Time estimates assume focused work and that Phase 0 confirms the approach.
